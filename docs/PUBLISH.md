# 初期公開版（PWA）の公開手順

`pwa/` フォルダの中身が、公開するアプリのすべてです（約200KB、外部ファイルなし）。

## 手元で試す（PC）
```
cd pwa
python -m http.server 8000
```
ブラウザで http://localhost:8000 を開く。一度開いたら、ネットを切って再読み込みしても動く。
スマホで試すには HTTPS の置き場所が必要（Service Worker は https か localhost でしか動かない）。

## 公開する
静的ファイルを置けるHTTPSのサーバーなら、どこでもよい。`pwa/` の中身をそのまま置く。
- Cloudflare Pages / Netlify：`pwa/` を公開フォルダに指定。`_headers` が読まれ、通信禁止の設定がHTTPヘッダーでも入る。
- GitHub Pages：そのまま置ける（`_headers` は無視される。ページ内の meta の設定は効く）。
- レンタルサーバー（deejei.tokyo など）：`/hair/` のようなフォルダに置く。可能なら `_headers` と同じ内容を .htaccess などで設定する。

## 公開前にやること
1. `pwa/app.js` 先頭の `SOURCE_URL` に、公開したリポジトリのURLを入れる（空のままだと「ソースコードは公開しています」の行は表示されない）。
2. `python build_pwa.py` を実行（engine.js のコピーと、sw.js のキャッシュ名の更新）。ファイルを直したら毎回実行する。
3. スマホで開き、機内モードで「撮影→解析→記録→書き出し」まで通す。
4. 「外に出ていないことを確かめる」で、外部への通信が0件であることを見る。

## 更新のしかた
ファイルを直す → `python build_pwa.py` → 置き直す。利用者の端末では、次に開いたときに新しい版が裏で入り、その次に開いたときから使われる。

## 入れていないもの（方針）
- アクセス解析、広告、外部フォント、外部スクリプト、アカウント、サーバー側の保存。
- 入れる場合は「通信なし」の約束が崩れるので、画面の説明とCSPも合わせて直す。

## 通信についての正確な説明
- ページのCSPは `connect-src 'none'`。ページのコードからの通信はブラウザが止める。
- 通信が起きるのは、ブラウザがこのアプリ自身のファイルを取りに行くとき（初回と更新確認）だけ。写真・結果・記録は送らない。
- `_headers` 側は `connect-src 'self'`（Service Worker が自分のファイルを取るため）。ページ側は meta と両方がかかるので、厳しい方（通信なし）になる。
